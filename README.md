# Triosteum

Экосистема для производств: доска блоков кода (HTML, Python, C++, C#, 1С) и офисная среда (документы, таблицы, презентации, формы, маршруты согласования).

Сейчас это клиент, который целиком работает в браузере, а данные хранит в localStorage. Следующий этап — сервер (см. документ «Triosteum: план и архитектура сервера»).

## Быстрый старт

Нужен только [Node.js](https://nodejs.org) 20 или новее. Других зависимостей у сборки нет.

```bash
npm run build     # собрать docs/index.html
npm run dev       # пересобирать при каждом сохранении файла в src/
```

Чтобы посмотреть результат, откройте `docs/index.html` в браузере. После правки обновите страницу.

Проверки в настоящем браузере:

```bash
npm install
npx playwright install chromium
npm test
```

### Как устроен код

Все файлы из `src/app` при сборке склеиваются по порядку из `manifest.json` в одну функцию. Поэтому они видят переменные и функции друг друга без `import`. Правила:

- **Новый файл** добавьте в `manifest.json` в нужное место. Функции (`function имя(){}`) доступны из любого файла. Переменные (`var`) получают значение только к моменту выполнения своей строки, поэтому их нужно объявлять раньше, чем их используют при запуске.
- **Глобальное состояние:** `S` — состояние интерфейса, `G` — схема текущего пространства, `UI` — личные настройки, `ENV` — текущая среда.
- **Данные читаем и пишем только через `Store` и `Repo`** (`src/app/core/store.js`). Напрямую обращаться к `localStorage` нельзя: так переход на сервер затронет один файл.

Следующий шаг рефакторинга — постепенно перевести части на настоящие ES-модули и TypeScript, начиная с самых независимых (`office/calc.js`, `office/sanitize.js`, `core/store.js`).

## Хранилище и переход на сервер

`Repo` описывает, что именно хранится. Это и есть будущий API сервера:

| Метод | Что делает | Будущий запрос к серверу |
|---|---|---|
| `Repo.spaceList()` / `Repo.saveSpaceList(v)` | список пространств пользователя | `GET/PUT /api/spaces` |
| `Repo.space(id)` / `Repo.saveSpace(id, g)` | содержимое пространства (схема, файлы офиса) | `GET/PUT /api/spaces/{id}` |
| `Repo.removeSpace(id)` | удалить пространство | `DELETE /api/spaces/{id}` |
| `Repo.pref(name)` / `Repo.setPref(name, v)` | личные настройки: тема, окна, свои плагины | `GET/PUT /api/me/prefs/{name}` |

Под `Repo` лежит `Store` с подменяемым адаптером. Чтобы подключить сервер, нужно написать адаптер с пятью методами и включить его:

```js
var serverAdapter = {
  name: 'server',
  get: function (key) { /* строка из кэша или null */ },
  set: function (key, text) { /* положить в кэш, отправить на сервер; вернуть true */ },
  remove: function (key) { /* … */ },
  keys: function (prefix) { /* список ключей */ },
  watch: function (fn) { /* fn(key, текст) — когда сервер прислал изменения (WebSocket) */ }
};
Store.use(serverAdapter);
```

Приложение читает данные синхронно, поэтому серверный адаптер при входе загружает данные пользователя в кэш, а сохраняет в фоне. Синхронизация между вкладками уже работает через `Store.watch`. Тем же путём будут приходить изменения с сервера.

## Работа с сервером

Сервер запускается одной командой: `cp .env.example .env && docker compose up -d --build`. Подробности — в [`server/README.md`](server/README.md). Как поставить Triosteum на свой сервер с HTTPS и резервными копиями — [`deploy/README.md`](deploy/README.md).


Если страницу отдаёт сервер Triosteum, данные хранятся в облаке, иначе в браузере. Сервер вставляет в страницу данные пользователя (`window.TRIOSTEUM_BOOT`), и `server-adapter.js` включается автоматически. Что для этого должен уметь сервер, описано в [`server/API.md`](server/API.md).

- `server/db/001_init.sql` — схема PostgreSQL: организации, роли, сессии, пространства с версиями, настройки, журнал. Включена построчная защита, поэтому организация видит только свои строки. Проверка: `server/db/test_rls.sql`.
- `server/app/static/login.html` — страница входа и регистрации организации.
- `tests/mock-server.mjs` — тестовый сервер в памяти с тем же API. Запуск: `npm run serve:mock`, затем откройте http://localhost:8787.
- `tests/server-e2e.mjs` — сквозная проверка: регистрация, сохранение, перезагрузка, конфликт правок, перенос из браузера, выход (`npm run test:server`).

Как ведёт себя адаптер:
- Правки копятся ~0,8 с и уходят одним запросом.
- Если связи нет, появляется «нет связи — правки ждут», и отправка повторяется каждые 5 с.
- Если пространство одновременно изменил коллега, открывается его версия, а ваши правки сохраняются копией «… — мои правки».
- Перед закрытием вкладки неотправленные правки дожимаются.

## Выкладка на GitHub Pages

1. Загрузите репозиторий на GitHub.
2. Откройте Settings → Pages и выберите: Source — **GitHub Actions**. Сайт собирает и публикует workflow «Сайт на GitHub Pages» (`.github/workflows/pages.yml`) при каждом изменении `main`; первый раз его можно запустить вручную во вкладке Actions.
3. Через пару минут сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

После правки выполните `npm run build`, чтобы проверить результат. Собранный `docs/index.html` коммитить не нужно — он в `.gitignore`: GitHub Pages и сервер собирают его сами.

ИИ-функции (окно «AI», «Конструктор» с правками ИИ) вне claude.ai не работают, пока нет своего сервера с ИИ-прокси.

## Отраслевые среды

Склад, Производство, Финансы, Персонал, Продажи и Аналитика устроены одинаково: таблицы, документы, условия, выгрузки и Python — общие с «Офисом», плюс собственные расчётные блоки. Расчётный блок описывается в `src/app/envs/industry.js` функцией `opKind(id, название, описание, параметры по умолчанию, поля формы, apply, sum)`:

- `apply(rows, p, ctx)` получает записи от блоков выше по схеме и возвращает записи дальше; `ctx.ins` — записи по каждому входу отдельно, `ctx.table()` и `ctx.chart()` добавляют таблицу или диаграмму в окно результатов, `ctx.info` — строка итога;
- поля формы: `[ключ, подпись, тип]`, тип `f` — поле записи, `t` — текст, `n` — число, `s` — выбор.

Новая среда — вызов `industryEnv(id, {...})` с блоками, библиотекой и примером; дополнить существующую — `extendEnv(id, { ops, lib, colors, more })` в `industry-deep.js`. Общие для всех сред блоки (вычисление, группировка, период, дубли, объединение, план-факт, ABC, диаграмма, показатель, дашборд) — в `ops.js`; `ctx.item()` добавляет показатель или дашборд, `ctx.upItems()` отдаёт результаты блоков выше по схеме. Идентификатор среды — 2–12 латинских строчных букв (так проверяет сервер). Проверка всех примеров: `npm run test:envs`.

## Triosteum под свою компанию

Каждая организация наращивает Triosteum под себя; всё это видят только её сотрудники (на сервере — построчная защита по организации).

- **Библиотека компании** — сотрудник делится своим плагином, и он появляется в разделе «Компания» библиотеки у коллег.
- **Свои среды** — экран сред → «Своя среда»: название, цвет, значок и типы блоков из отраслевых сред.
- **Мастерская компании** (Ctrl+K → «Мастерская компании») — всё это в одном месте: у каждой доработки история версий и
  «Вернуть эту версию», плагины и расширения выключаются для всех одной кнопкой, журнал изменений показывает, кто, что и когда менял.
  Откатывать и выключать может автор или владелец организации (расширения — только владелец).
- **Расширения** — небольшие программы компании на JavaScript: свои команды в Ctrl+K (раздел «Расширения») и боковая панель.
  Собираются в **мастерской компании** (Ctrl+K → «Мастерская компании»): описание, разрешения, команды, код, ИИ пишет код по описанию,
  пробный запуск с журналом. Публикует владелец организации; каждый сотрудник включает расширение сам в «Расширения компании», увидев разрешения
  (читать доску, менять доску, видеть выделение, своё хранилище, панель, работа в фоне). Новая версия с новыми разрешениями снова спрашивает подтверждение.
  Команда может жить в Ctrl+K и/или в окне настроек блока (правая кнопка мыши) — тогда она получает id этого блока.
  Расширение с разрешением «работать в фоне» запускается вместе с Triosteum и реагирует на события: `triosteum.on("selection" | "space" | "change", fn)`.
  Разрешение «общие данные компании» (`triosteum.org.get/set/all`) даёт расширению общий для организации справочник:
  до 64 КБ на значение и 2 МБ на расширение, видят все, у кого оно включено, меняют редактор и владелец; в пробном запуске черновика —
  учебная копия только у автора. Панель расширения можно закрепить — она будет открываться сама при каждом запуске Triosteum.
  Обмен между компаниями — по желанию, файлом: «Скачать файлом» в мастерской → «Загрузить из файла…» в мастерской другой компании
  (загружается черновиком с предупреждением прочитать код; публикует их владелец).

Расширение работает в песочнице: `iframe sandbox="allow-scripts"` без `allow-same-origin` и с политикой безопасности без сети. Оно не видит страницу
Triosteum, её хранилище (ключи ИИ, пространства) и куки, не делает запросов к серверу от имени пользователя; с приложением говорит только через объект
`triosteum` (`board.get/selection/add/update/remove/connect/note`, `ui.toast/openPanel/closePanel`, `storage.get/set`, `command`, `on("change")`),
и каждое действие проверяется по разрешениям. Изменения одной команды отменяются одним Ctrl+Z. Расширение живёт во вложенном iframe внутри обёртки
с CSP `frame-src 'none'`: переход на внешний адрес браузер блокирует ещё до запроса, а попытка останавливает расширение. Остаточные побочные каналы
браузера полностью не закрыть, поэтому публикует только владелец, а чтение доски — явное разрешение.
Код: `src/app/ext/ext.js` (песочница и разрешения), `src/app/ext/workshop.js` (мастерская), сервер — `server/app/orglib.py`.

- **Формулы.** `src/app/docs/functions.js` — 126 функций с русскими и английскими именами (математика, тригонометрия, статистика, СУММЕСЛИ/СЧЁТЕСЛИ, ВПР/ИНДЕКС/ПОИСКПОЗ, логика, текст, даты, ПЛТ/ЧПС/ВСД). - **Схема файлов** (`office/file-map.js`) — вкладка «Офиса»: файлы как блоки, связи находятся по формулам между книгами, живым вставкам и формам; протягивание линии создаёт связь (живая копия листа, итоги, вставка в документ или слайд). «Скомпилировать» — пересчёт по порядку зависимостей с отчётом об ошибках и циклах. Проверка: `npm run test:office`.
- **Фоторедактор** (`office/image.js`) и **векторная графика** (`office/vector.js`) — файлы `image` и `vector`; доступны в «Офисе» и в отдельных средах `photo` и `vector` (`envs/graphics.js`). Проверка: `npm run test:graphics`.

## Совмещение всего со всем

- **Общий буфер** (`workspace/universal.js`). Блоки, скопированные в любом пространстве, вставляются в любое другое — со своим кодом, языком и цветами; на блоке другой среды есть метка его среды. В системный буфер пишется метка `TRIOSTEUM-CLIP:`, поэтому вставка работает и между вкладками браузера. Картинки и текст из буфера вставляются на доску через окно «Как вставить?».
- **Единая компиляция.** Если на доске есть блоки разных сред (код, таблицы, документы, расчёты), вся схема выполняется одним маршрутом (`docs/route-run.js`): Python — в браузере или на сервере, HTML-блоки — в результатах, данные идут дальше по связям.
- **Блок в родной среде.** Двойной клик по блоку открывает его; блок другой среды открывается в своей среде **в этом же пространстве** (без копий): правки сохраняются сразу, плашка «Вернуться в …» возвращает прежнюю среду.
- **C++, C# и 1С без сервера** (`editor/lang-cfam.js`, `editor/lang-bsl.js`, `editor/lang-run.js`). Встроенные исполнители работают прямо в браузере, в том числе на GitHub Pages.
  - **C++**: классы и структуры с конструкторами и наследованием, виртуальные методы, перегрузка операторов (`operator+`, `operator<` для `std::sort`), шаблоны функций, пространства имён, `enum class`, ссылки `T&` (в том числе `for (auto& x : v)`), `static`-переменные функций, итераторы (`begin/end`, `*it`, `it->first`), `std::vector/map/set/pair/queue/stack/priority_queue`, `<algorithm>` и `<numeric>`, `std::function`, `std::stringstream`, `printf`, `std::fixed`/`setprecision`/`setw`, исключения `std::runtime_error` и др.
  - **C#**: классы, интерфейсы, абстрактные классы, `base`, перегрузки конструкторов (`: this(…)`/`: base(…)`), свойства с `get/set`, записи и `with`, кортежи и деконструкция, локальные функции, методы расширения, обобщённые методы, `switch`-выражения и сопоставление с образцом (`is Pt p`, `>= 90`, `and/or/not`, свойства), LINQ — и методами, и запросом `from … where … orderby … select`, `async/await`, `HashSet/Queue/Stack`, своё исключение и несколько `catch`, `string.Format` с выравниванием.
  - **1С**: встроенный язык (параметры по ссылке и `Знач`, `Вычислить`, `Выполнить`, `ЗаполнитьЗначенияСвойств`, `ЧтениеJSON`/`ЗаписьJSON`, `ТипЗнч`/`Тип`, даты, строки), таблицы значений, структуры, соответствия и язык запросов: `ВЫБРАТЬ … ПОМЕСТИТЬ`, пакеты через `;`, соединения, `ВЫБОР КОГДА`, таблицы из параметров (`ИЗ &Таблица`).
  - Запросы 1С работают над данными схемы: источник «Документ.ЗаказКлиента» — это входная таблица блока (или её часть с тем же именем). Поля сопоставляются по синонимам (`revenue` ↔ «Выручка»). C# читает таблицы рабочего стола через `new XLWorkbook("Имя таблицы")`. Без входа блок запускается на демо-данных.
  - **Секреты**: Настройки (шестерёнка) → «Секреты для блоков». C# берёт их через `Secrets.Get("ИМЯ")`, 1С — через `ПолучитьСекрет("ИМЯ")`. Значения хранятся только в браузере (по умолчанию — до закрытия вкладки) и не попадают в код и файлы пространства.
  - Ограничения браузера: почта (SMTP) и запросы к сайтам, которые не разрешают обращения из браузера (CORS), — только на сервере; ошибка об этом говорит прямо.
  - Проверка: `node tests/foreign.test.cjs` и `node tests/lang-corpus.test.cjs` — набор типичных программ (`tests/lang-cases/`), у каждой ответ сверен с настоящим компилятором/платформой.
- **Python без CDN.** Pyodide лежит рядом с приложением (`docs/vendor/pyodide/`, из npm-пакета `pyodide@0.26.4`), поэтому Python-блоки работают, даже когда jsdelivr недоступен; CDN — запасной вариант.
- **Сквозная компиляция** (`workspace/cross-run.js`). В запросе к ИИ-архитектору можно упоминать то, что лежит в других пространствах и средах: блоки, таблицы и документы «Офиса», целые пространства (точнее всего — названием в «кавычках»). Под полем задачи сразу видно, что найдено. «Собрать схему» передаёт найденное ИИ, и он ставит это в схему ссылками, а не пишет заново; «Собрать из готового и скомпилировать» работает без ИИ: ставит найденное (источники → обработка → результаты) и сразу запускает компилятор. Блок-ссылка (значок ↗) при каждом запуске берёт свежий код или данные из источника; двойной клик открывает источник в его пространстве и среде; если источник удалят, работает сохранённая копия. Проверка: `npm run test:cross`.
- **Окно компилятора** (`board/compiler.js`). «Запустить» открывает плавающее окно: перетаскивается за заголовок, меняет размер за угол, сворачивается и разворачивается. Вкладки: «Журнал», «Блоки» (статус и время каждого блока), «Ошибки» (щелчок — показать блок на доске, двойной — открыть код, с подсказкой, что делать), «Вывод» (что напечатали программы, по блокам). Кнопки: «Запустить», «Выделенные» (только выделенные блоки, их входы берутся из прошлого запуска), «Стоп» (после текущего блока), копирование и сохранение журнала в .txt. Проверка: `npm run test:compiler`.
- **Переключатель ИИ** в шапке слева от шестерёнки (`ai/claude-link.js`). Пока он включён, все ИИ-функции Triosteum (помощник блока, архитектор, конструктор, бэкенд, ИИ офиса) работают через выбранный ИИ; выключение возвращает прежний. Стрелка рядом открывает выбор поставщика:
  - **Claude** — в claude.ai без ключа, иначе со своим ключом API Anthropic (Opus 5.5, Sonnet 5.5, Haiku 5.5). API Anthropic доступен не во всех странах.
  - **Ollama** — бесплатная модель на своём компьютере, без интернета: установить Ollama, `ollama pull qwen2.5-coder:7b`, разрешить запросы со страницы (`OLLAMA_ORIGINS="*"`), нажать «Найти модели».
  - **Свой ИИ** — любой сервис с API в формате OpenAI (`/chat/completions` с потоком): облачные модели, LM Studio, vLLM, сервер компании. Задаются название на переключателе, адрес, ключ и модель; сервис должен разрешать запросы из браузера (CORS), иначе подключайте его через сервер Triosteum (`AI_PROVIDER`).
  - Ключи хранятся только в браузере (до закрытия вкладки или, по галочке, на устройстве) и отправляются только выбранному сервису. Проверка: `npm run test:compiler`.
- **Автоматизация в графике.** У «Фоторедактора» и «Векторной графики» есть доска «Автоматизация» с таблицами, расчётами, кодом и блоком «Картинка из данных», который кладёт диаграмму файлом на рабочий стол.
- **Точки на связях.** Потрясти точку — отцепить подключённые к ней блоки (пустую — снять со связи); утянуть точку далеко от связи — она становится узлом, блоки остаются подключены. Отросток к точке снимается протягиванием за любое место. Проверка: `npm run test:board`.
- **Желе.** Блоки, заметки, файлы на схеме и значки рабочего стола вытягиваются по ходу движения и пружинят, когда их отпускают (`ui/jelly.js`). Физика пружин — библиотека [wobble](https://github.com/skevy/wobble) (MIT), встроена в сборку (`app/vendor/wobble.js`): решение аналитическое, поэтому движение одинаково ровное на телефоне и мониторах 60/120 Гц. Пальцем блок движется строго за пальцем. Отключается вместе с анимациями.
- **Варианты блоков.** В меню «Добавление элементов» наведение на «Блок» сразу показывает типы блоков своей среды: расчёты среды, общие расчёты, данные и документы, код.
- **Среда написания кода под язык** (`editor/highlight.js`). Редактор сам подстраивается под язык блока или плагина: Python — как PyCharm (Darcula), C++ и C# — как Visual Studio (тёмная тема), HTML/JavaScript/JSON — как VS Code (Dark+), 1С — как Конфигуратор (светлая, красные ключевые слова, синие имена, зелёные комментарии, язык запросов в строках). При создании плагина рядом с языком видно, какая среда откроется. Подсветка есть и в ответах ИИ, коде схемы и в коде, вставленном в документы. Проверка: `node tests/highlight.test.cjs`.
- **Встряхивание** (`board/shake.js`). Зажать блок и потрясти — его связи переходят на новый узел на его месте; потрясти узел — связи отцепляются. На схеме файлов встряхивание файла открепляет все его связи (содержимое остаётся).
- **Вставка файлов друг в друга** (`office/insert.js`): картинки поверх ячеек таблицы, таблицы и тексты картинкой или вектором, документы в слайды, заголовки таблицы — в вопросы формы. Если способов несколько — окно выбора. Вставка помнит источник: это связь на схеме файлов, её можно открепить (клик по связи → Delete или ×) или обновить.
- **Схема файлов**: ПКМ по пустому месту — меню (создать файл, заметка, картинка, вставить, настройки), × и комментарии на блоках, заметки и картинки на схеме, Shift+рамка, Ctrl+A/D/Z/Y, стрелки, Delete.
- **Формат `.tsm`** (`workspace/files-io.js`): `kind:"space"` — всё пространство, `kind:"files"` — выбранные файлы со связями и комментариями, `kind:"blocks"` — блоки доски. Старые `.triosteum.json` открываются как раньше.
- **Шестерёнка** в шапке открывает настройки в любой среде и на любой вкладке.
- **Кнопки у любого края** (`ui/docks.js`). Любую кнопку панели слева можно перетащить мышью или пальцем к верхнему, нижнему или правому краю — там появляется своя панель (порядок — по месту отпускания); перетащить назад — вернуть влево. Кнопки меняются местами внутри любой панели, в том числе левой: перетаскиванием между другими кнопками или стрелками в Персонализации. То же в Персонализации: у каждой кнопки выбор «Слева / Сверху / Снизу / Справа» и «Вернуть все кнопки на панель слева». Меню и подсказки открываются в сторону от своей панели. Расположение запоминается. Проверка: `npm run test:docks`.
- **Очистка** — «Пространство → Очистка» и тот же раздел в Персонализации: очистить доску, это пространство целиком, все пространства среды, все пространства, удалить все пространства, сбросить оформление и панели, удалить секреты и ключи ИИ. Каждое действие подтверждается в окне; последнее можно вернуть пунктом «Вернуть» до перезагрузки страницы.
- **Закреплённые шапки**: во всех окнах с прокруткой (настройки, ИИ, экосистема, карточка блока, меню, диалоги) заголовок с кнопкой «Закрыть» остаётся на месте, прокручивается только содержимое.
- **Быстродействие**: сетка доски — отдельный слой, который только сдвигается; при перетаскивании блока перерисовываются только его связи, и они живут в отдельном лёгком слое; во время движения доски не обновляются строка состояния, мини-карта и размытие заметок. На доске из 160 блоков при перетаскивании время кадра сократилось примерно в 4 раза, при панораме — в 2.
- **Редактор тем** (`ui/theme-editor.js`), как темы чатов в Telegram: карандаш на любой теме — изменить её (в том числе встроенную; «Вернуть как было» восстанавливает исходную), «Создать тему» — своя тема. Основа — фон и акцент, остальные цвета подбираются сами (кнопка «Подобрать остальные цвета» и готовые фоны), плюс тонкая настройка всех 11 цветов, живой предпросмотр и предупреждение о плохой читаемости. Изменения видны сразу во всём приложении, «Отмена» возвращает прежнее. Темой можно поделиться кодом и вставить чужой код.
- Проверка: `npm run test:universal`.

## Логотип

Все версии знака и логотипа — в папке `brand/`: горизонтальный и вертикальный логотип для светлого и тёмного фона, знак в фирменных цветах, белый и чёрный, иконка приложения и фавиконки. В приложении знак встроен один раз как SVG-символ `#tMark` и берёт цвета из темы (`--lg1..3`); фавиконка и иконка для iOS встроены в страницу. Сервер отдаёт иконки по адресу `/brand/…` — их используют страница входа и письма.
