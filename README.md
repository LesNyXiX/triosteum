# Triosteum

Экосистема для производств: доска блоков кода (HTML, Python, C++, C#, 1С) и офисная среда (документы, таблицы, презентации, формы, маршруты согласования).

Сейчас это клиент, который целиком работает в браузере, а данные хранит в localStorage. Следующий этап — сервер (см. документ «Triosteum: план и архитектура сервера»).

## Быстрый старт

Нужен только [Node.js](https://nodejs.org) 20 или новее. Других зависимостей у сборки нет.

```bash
npm run build     # собрать docs/index.html
npm run dev       # пересобирать при каждом сохранении файла в src/
```

Чтобы посмотреть результат, откройте `docs/index.html` в браузере. После правки обновите страницу.

Проверки в настоящем браузере:

```bash
npm install
npx playwright install chromium
npm test
```

### Как устроен код

Все файлы из `src/app` при сборке склеиваются по порядку из `manifest.json` в одну функцию. Поэтому они видят переменные и функции друг друга без `import`. Правила:

- **Новый файл** добавьте в `manifest.json` в нужное место. Функции (`function имя(){}`) доступны из любого файла. Переменные (`var`) получают значение только к моменту выполнения своей строки, поэтому их нужно объявлять раньше, чем их используют при запуске.
- **Глобальное состояние:** `S` — состояние интерфейса, `G` — схема текущего пространства, `UI` — личные настройки, `ENV` — текущая среда.
- **Данные читаем и пишем только через `Store` и `Repo`** (`src/app/core/store.js`). Напрямую обращаться к `localStorage` нельзя: так переход на сервер затронет один файл.

Следующий шаг рефакторинга — постепенно перевести части на настоящие ES-модули и TypeScript, начиная с самых независимых (`office/calc.js`, `office/sanitize.js`, `core/store.js`).

## Хранилище и переход на сервер

`Repo` описывает, что именно хранится. Это и есть будущий API сервера:

| Метод | Что делает | Будущий запрос к серверу |
|---|---|---|
| `Repo.spaceList()` / `Repo.saveSpaceList(v)` | список пространств пользователя | `GET/PUT /api/spaces` |
| `Repo.space(id)` / `Repo.saveSpace(id, g)` | содержимое пространства (схема, файлы офиса) | `GET/PUT /api/spaces/{id}` |
| `Repo.removeSpace(id)` | удалить пространство | `DELETE /api/spaces/{id}` |
| `Repo.pref(name)` / `Repo.setPref(name, v)` | личные настройки: тема, окна, свои плагины | `GET/PUT /api/me/prefs/{name}` |

Под `Repo` лежит `Store` с подменяемым адаптером. Чтобы подключить сервер, нужно написать адаптер с пятью методами и включить его:

```js
var serverAdapter = {
  name: 'server',
  get: function (key) { /* строка из кэша или null */ },
  set: function (key, text) { /* положить в кэш, отправить на сервер; вернуть true */ },
  remove: function (key) { /* … */ },
  keys: function (prefix) { /* список ключей */ },
  watch: function (fn) { /* fn(key, текст) — когда сервер прислал изменения (WebSocket) */ }
};
Store.use(serverAdapter);
```

Приложение читает данные синхронно, поэтому серверный адаптер при входе загружает данные пользователя в кэш, а сохраняет в фоне. Синхронизация между вкладками уже работает через `Store.watch`. Тем же путём будут приходить изменения с сервера.

## Выкладка на GitHub Pages

1. Загрузите репозиторий на GitHub.
2. Откройте Settings → Pages и выберите: Source — Deploy from a branch, ветка `main`, папка `/docs`.
3. Через минуту сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

После каждой правки выполните `npm run build` и закоммитьте обновлённый `docs/index.html`.

ИИ-функции (окно «AI», «Конструктор» с правками ИИ) вне claude.ai не работают, пока нет своего сервера с ИИ-прокси.
